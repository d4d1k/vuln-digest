# Vuln Digest

Небольшой Python-сервис, который собирает сведения о новых критичных уязвимостях и новых записях каталога CISA KEV, формирует русскоязычную сводку и отправляет её в Telegram.

Для генерации текста можно подключить бесплатную модель OpenRouter. Если LLM недоступна или не настроена, сервис формирует резервный отчёт непосредственно из полученных фактов.

## Возможности

- получение CVE из NVD API 2.0;
- отбор новых уязвимостей с CVSS ≥ 9.0, включая CVSS 4.0;
- получение новых записей CISA Known Exploited Vulnerabilities Catalog;
- объединение сведений NVD и KEV по идентификатору CVE;
- настраиваемые период сбора и количество элементов Top-N;
- генерация сводки через OpenRouter;
- резервный шаблонный отчёт без LLM;
- отправка длинных отчётов несколькими сообщениями Telegram;
- хранение отправленных записей в SQLite и защита от повторов;
- однократный запуск или постоянная работа по интервалу.

Сторонние Python-зависимости не требуются.

## Источники данных

| Сервис | Назначение |
| --- | --- |
| [NVD](https://nvd.nist.gov/developers/vulnerabilities) | Описание CVE, дата публикации, CVSS, CWE, конфигурации и ссылки |
| [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) | Подтверждение эксплуатации, дата добавления и требуемые действия |
| [OpenRouter](https://openrouter.ai/) | Формирование человекочитаемой сводки на основе собранных данных |
| Telegram Bot API | Доставка отчёта |

LLM получает только уже собранные структурированные данные. Она не используется как самостоятельный источник фактов об уязвимостях.

## Требования

- Python 3.11 или новее;
- доступ к NVD и CISA по HTTPS;
- бот Telegram и ID чата для отправки;
- ключ OpenRouter только для LLM-версии отчёта;
- ключ NVD API необязателен, но повышает лимиты запросов.

## Установка

```bash
git clone git@github.com:d4d1k/vuln-digest.git
cd vuln-digest
cp .env.example .env
chmod 600 .env
```

Откройте `.env` в текстовом редакторе и заполните необходимые параметры. Файл добавлен в `.gitignore` и не должен попадать в Git.

## Настройка

| Переменная | Значение по умолчанию | Описание |
| --- | --- | --- |
| `NVD_API_KEY` | пусто | Необязательный [ключ NVD API](https://nvd.nist.gov/developers/request-an-api-key) |
| `OPENROUTER_API_KEY` | пусто | Ключ OpenRouter; без него используется резервный отчёт |
| `OPENROUTER_MODEL` | `openrouter/free` | Модель OpenRouter |
| `TELEGRAM_BOT_TOKEN` | пусто | Токен бота, полученный через `@BotFather` |
| `TELEGRAM_CHAT_ID` | пусто | ID пользователя, группы или канала |
| `DIGEST_TOP_N` | `10` | Максимум записей в каждой категории |
| `DIGEST_LOOKBACK_HOURS` | `24` | Период сбора новых записей |
| `DIGEST_INTERVAL_HOURS` | `24` | Интервал между запусками в режиме daemon |
| `DIGEST_DB_PATH` | `data/state.sqlite3` | Путь к базе отправленных записей |

Доступность и лимиты бесплатных моделей OpenRouter могут меняться. При необходимости замените `OPENROUTER_MODEL` на другую поддерживаемую модель.

### Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Отправьте созданному боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<TOKEN>/getUpdates`, подставив токен.
4. Найдите `message.chat.id` и укажите его в `TELEGRAM_CHAT_ID`.

Для канала или группы бота необходимо добавить туда и выдать право публиковать сообщения.

## Запуск

### Проверка без отправки

```bash
python3 vuln_digest.py run --dry-run
```

Команда выполняет реальные запросы к NVD и CISA и выводит отчёт в терминал. Если задан ключ OpenRouter, будет также вызвана LLM. Сообщение в Telegram не отправляется, а записи не отмечаются как обработанные.

Для подробного логирования:

```bash
python3 vuln_digest.py --verbose run --dry-run
```

### Однократная отправка

```bash
python3 vuln_digest.py run
```

После успешной отправки записи сохраняются в SQLite. При следующем запуске они не будут повторно включены в ту же категорию.

### Постоянная работа

```bash
python3 vuln_digest.py daemon
```

В этом режиме сервис запускается сразу, а затем повторяет сбор через число часов из `DIGEST_INTERVAL_HOURS`. Остановка — `Ctrl+C`.

Для автоматического запуска после перезагрузки можно использовать systemd или cron. Пример ежедневного задания cron в 09:00:

```cron
0 9 * * * cd /home/dud1k/Desktop/vuln-digest && /usr/bin/python3 vuln_digest.py run >> /tmp/vuln-digest.log 2>&1
```

При использовании cron не запускайте одновременно встроенный режим `daemon`.

## Логика отбора

### Новые критичные уязвимости

- CVE опубликована в течение `DIGEST_LOOKBACK_HOURS`;
- основная доступная оценка CVSS не ниже 9.0;
- записи со статусом `Rejected` исключаются;
- сортировка по CVSS, затем по дате публикации;
- выбираются не более `DIGEST_TOP_N` ещё не отправленных записей.

### CISA KEV

- дата `dateAdded` входит в период сбора;
- выбираются не более `DIGEST_TOP_N` новых записей;
- для каждой записи дополнительно запрашиваются сведения из NVD.

Если CVE входит в обе категории, формируется одна объединённая карточка. Состояние хранится отдельно для категорий `critical` и `kev`: уязвимость может снова попасть в отчёт, если позже её добавят в KEV.

## Ограничения

- Дата публикации NVD не обязательно совпадает с фактической датой обнаружения уязвимости.
- KEV подтверждает известную эксплуатацию, но не ранжирует уязвимости по частоте атак.
- NVD и KEV не всегда содержат точную версию патча или подробности эксплуатации. Такие сведения следует подтверждать в рекомендациях производителя по ссылкам из отчёта.
- Если отправка Telegram завершилась ошибкой, записи не считаются обработанными и будут повторно рассмотрены при следующем запуске.
- Встроенный `daemon` не является системной службой и сам не восстанавливается после перезагрузки.
